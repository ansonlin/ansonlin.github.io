Kubernetes HA環境概述

由於資源限制，原本應該獨立的HA Proxy主機，因資源夠大，所以合併作為Worker01用了。
而K8S Cluster 主要運作的容器服務都在 worker 上面(預設上 master 是不開放運行的，除非特別取消這個限制)，因此資源上(尤其是記憶體)不妨給 worker 多一些。
為了快速部署，完成一台後可直接做成範本，複製成其它台VM。

  1. HA Proxy角色
    lb01 10.40.46.101 (4vCPU、16GBvRAM、300GB HDD)

  2. Masters角色
    master01 10.40.141.101 (2vCPU、4GBvRAM、40GB HDD)
    master02 10.40.141.102 (2vCPU、4GBvRAM、40GB HDD)
    master02 10.40.141.102 (2vCPU、4GBvRAM、40GB HDD)

  3. Workers角色
    worker01 10.40.46.101 (4vCPU、16GBvRAM、300GB HDD)
    worker02 10.40.141.112 (2vCPU、8GBvRAM、40GB HDD)
    worker03 10.40.141.113 (2vCPU、4GBvRAM、40GB HDD)

由於第一台會先做成範本，所以先加入hosts，方便後續進行。

Kubernetes HA常见问题

加入集群過程需要檢查kubelet服務，若遇到檢查失敗問題，建議先停用開機自動啟動kubelet服務，重開機後再手動執行啟動，然後再加入自動啟動

# systemctl disable kubelet && reboot
# systemctl enable kubelet && systemctl start kubelet
