使用Gitlab CI/CD進行程式碼自動打包

Posted on 2020-04-06

目的：透過Gitlab CI/CD的功能，來撰寫gitlab-ci.yaml，自動化進行程式碼測試、構建、佈署。

Gitlab Runner

安装Gitlab Runner

本章節透過docker-compose，佈署gitlab runner環境供pipeline使用。

$ docker volume create gitlab-runner-config && vi docker-compose.yaml

$ docker-compose -f docker-compose.yml up -d

註冊 Gitlab-runner

此步驟註冊gitlab runner，首先必須先取得gitlab url及token，然後進入容器進行註冊。
more info: gitlab runner register

(1) 取得gitlab url&token
開啟 gitlab站台 > Admin Area > Runers >

(2) gitlab-runner註冊

NPM

npm打包設定檔

透過npm打包會使用到的相關檔案有:
(1) .npmrc: 用來放置打包會用的設定檔案，或可使用npm config來設置(Global: $HOME/.npmrc、每個專案: project/.npmrc)。
(2) package.json:描述打包使用的相依套件、test/build/lint/publish階段的command…等等。

$ vi .npmrc
設置root權限，避免安裝失敗。

$ vi package.json

取得NPM Repository token

說明：此處透過一台測試主機,透過npm登陸後，由global .npmrc檔案取的NPM TOKEN，然後將這token設定到gitlab-ci.yml。

設置gitlab CI/CD變數

步驟：gitlab 專案 > Settings > CI/CD > Secret variables >

Troubeshooting

Gitlab: Artifacts Max size

Admin Area > Settings > Continuous Integration and Deployment > Maximum artifacts size (MB) > 1024

Gitlab: Enable untagged jobs

Open gitlab > Admin Area > Runers > Runner token > Choose “Indicates whether this runner can pick jobs without tags”

Gitlab: Add Personal Access Tokens

Users > Settings > Access Tokens >

Gitlab-Runner: Get GitlabCI environment variables

進入dind容器確認
$ docker exec -it dind sh
$ docker ps
$ docker inspect YOUR-CONTAINER-ID (在Config底下)
